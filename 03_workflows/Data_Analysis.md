# Workflow: Data Analysis

## Task Context

A research question and authorised dataset, statistical output, interview/focus-group material, documents, field notes, or mixed-method evidence within a named project.

## Required Inputs

- Research question, constructs, hypotheses or analytic objectives.
- Data provenance, collection method, sample, codebook/data dictionary, and ethics/access status.
- Raw or processed data, software output, or coded extracts actually available.
- Planned method and relevant module/supervisor guidance.

If confidential data cannot be shared, work from de-identified aggregates, metadata, or student-run output. Do not ask the student to upload protected data merely for convenience.

## Method

1. **Confirm the analytic question:** identify what the analysis can and cannot answer.
2. **Verify provenance and preparation:** record sample construction, missingness, exclusions, transformations, coding decisions, and version.
3. **Select the analysis path:** quantitative, qualitative, or mixed methods; justify fit rather than defaulting to a familiar technique.
4. **Run the appropriate checks:** follow the path-specific requirements below.
5. **Separate result from interpretation:** record observed output first, then bounded inference, alternatives, and limitations.
6. **Link back to the project:** update the claim–evidence matrix and identify implications for theory, practice, and the research question.
7. **Preserve reproducibility:** retain syntax, formulas, coding framework, decision log, and output version where permitted.

### Quantitative path

- Inspect variable definitions, sample characteristics, distributions, missing data, and data-quality issues before inferential analysis.
- Check the assumptions relevant to the chosen model; do not use a generic checklist detached from the method.
- Report magnitude and uncertainty—such as effect size and confidence interval—where appropriate, not only statistical significance.
- Distinguish association, prediction, and causal identification. Causal language requires a defensible design, not merely a significant coefficient.
- Record model specification, reference categories, transformations, exclusions, robustness checks, and software output.

### Qualitative path

- Define the analytic approach and unit of analysis.
- Maintain a coding framework and audit trail; separate participant text, descriptive code, interpretive theme, and researcher inference.
- Look for negative cases, rival explanations, context, and variation rather than selecting only vivid quotations.
- Address reflexivity, credibility, transferability, and limitations using the standards appropriate to the chosen methodology.
- Do not treat code frequency alone as prevalence, importance, or causal evidence.

### Mixed-method path

- Analyse each strand according to its own quality requirements.
- State when and how strands are connected, compared, or integrated.
- Explain convergence, complementarity, and contradiction rather than forcing agreement.

## Output

- Analysis objective and dataset/evidence version.
- Preparation and decision log.
- Method and assumption rationale.
- Observed results with traceable output or extracts.
- Interpretation, alternative explanations, uncertainty, and limitations.
- Claim–evidence updates and next analysis decision.

## Gaps

Record missing provenance, codebook, ethics/access basis, raw output, assumptions, sample information, analysis rationale, negative cases, robustness checks, or supervisor decisions.

## Next Action

Complete the earliest missing step that could materially change the validity of the result, beginning with provenance and data quality before more complex analysis.
